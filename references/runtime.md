# Find tools before declaring a capability unavailable

Use this procedure for setup, attachment conversion and validation. Reuse a verified runtime from the private profile, but check that it is still callable in the current host. Do not assume the interactive shell's PATH, a WindowsApps python alias, or a conventional installation folder describes all installed software. Never tell the user that software is absent after checking only PATH or a couple of guessed paths.

1. Read actual host permissions, project instructions and the private profile. Distinguish project authorization from executable access. Do not scan unrelated personal folders or private data. For local tasks, use the host's dependency/runtime locator when available (in Codex desktop: load_workspace_dependencies); otherwise inspect available runtime tools and documented system installation locations. Keep the workflow usable without Codex: the requirement is verified authorized tools, not a particular locator API. In Claude Code, <plugin> in helper commands is the folder two levels above the running skill's base directory (the installed copy under ~/.claude/plugins/cache/); scripts/ is installed with the skills.
2. Locate a real Python executable from saved runtime.python or the host bundle before trying aliases. Test its version and import of pypdf in that same executable. A module missing from one interpreter does not mean it is absent from all available runtimes. Do not install packages without authorization. The attachment helper requires pypdf; if no suitable runtime is available, explain that specific dependency rather than claiming PDFs cannot be handled.
3. For YAML validation, use saved runtime.rscript/r_library (or legacy equivalents), inspect known R installations and the user's versioned R library when needed, then test library(yaml) with that exact R and R_LIBS_USER. The default R library may omit packages installed in the user's library. A read-only package probe does not authorize R/cv.R or Quarto rendering. Use another already available safe YAML parser only when necessary and disclose differences; do not repeatedly guess module names or install dependencies implicitly.
4. For PPT/PPTX, prefer a verified Windows PowerPoint COM registration probe over searching only for POWERPNT.EXE. Check Start-menu application inventory, including Microsoft.Office.Desktop Store installations, and Windows registration when the host permits it. A Store installation can work through PowerPoint.Application without an executable on PATH or a conventional Office folder. Prefer saved runtime.powershell or an available pwsh; the helper uses pwsh before Windows PowerShell. If shell discovery differs from the host's configured runtime, save the verified absolute runtime.powershell path privately. Test an actual export with a synthetic deck in authorized private storage before claiming conversion works. Never use an unreviewed real patient presentation as a test fixture.
5. If PowerPoint is unavailable, check a saved attachments.soffice executable, PATH and actual LibreOffice installation locations. The helper validates an explicit saved absolute path and, when no path is configured and PATH has no soffice, checks LibreOffice/program/soffice.exe under the Windows ProgramW6432, ProgramFiles and ProgramFiles(x86) roots and standard Program Files locations. This bounded search does not establish absence everywhere. An invalid configured path or blocked/failed/timed-out PowerPoint registration probe is an unresolved runtime issue, not proof that Office is absent. Converter discovery does not itself verify export capability. A failed export is not proof of an absent converter. Read the error and distinguish COM registration, launch permission, execution policy, timeout, missing source and export failure. Respect execution policies; do not silently set Bypass or change machine/user policies. Use a permitted runtime or the host's normal approval mechanism when required. Do not close the user's existing PowerPoint session.
6. Use authorized private staging folders for scratch files, including converter profiles. Generic OS temp paths can be virtualized or blocked in a sandbox. A scratch-folder denial is not a conversion or data-validation failure. Verify a new uniquely named directory is within the intended writable workspace; do not broaden filesystem scope or use public record folders for private scratch data. Keep original inputs and outputs separate. Host approval may be necessary for desktop automation even when folder writes are allowed.
7. Save only verified executable paths, library paths, tested capabilities, date and provenance in the private profile; never package machine-specific paths. Preserve unknown profile keys and back up any existing profile uniquely before changes. Reuse dated tests without repeating work unnecessarily, and retest when the host/runtime changes or a failure warrants it. A successful synthetic export verifies the toolchain, not a later deck's layout or privacy.

On failure, report what was actually checked and the specific unresolved capability. If the host supports a normal escalation flow for a permission failure, use it rather than claiming the program is missing or bypassing restrictions. Keep optional attachments pending while completing independent, authorized record work. Installation of this plugin grants neither runtimes nor filesystem permissions.

For PubMed network access use [the selected-tool preflight and identity workflow](pubmed-discovery.md). Inspect known restrictions before the intended call; avoid repeat known-blocked attempts, arbitrary connectivity probes or invented blanket permission grants. A network failure is not an empty search result.

For the bundled Word CV, R already reports missing packages through library(). Do not add a parallel installer or infer compatibility from presence alone. The starter adds one early check that officer exports run_tab, which its paragraph builder needs, before reading records or creating outputs. It reports the installed version and asks for a reviewed upgrade in the selected library followed by restarting R. No numerical minimum is guessed, and no upgrade runs automatically. This guard is in the bundled starter only; do not patch an existing user CV script without authorization.

For first-time setup, use the [local readiness table](readiness.md) after selecting goals and resolving saved/host runtimes. It supplements initialize.py probe, preserves the officer capability check and requires no package installation or project execution.
