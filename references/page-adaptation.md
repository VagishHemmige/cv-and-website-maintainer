# Add or hide a website page

Use on a user's request during initialization or later authorized website work. No exhaustive page catalog or new required questionnaire. Ask the next needed question one at a time. Reuse actual project instructions and current permissions; routine record maintenance is not permission to edit Quarto/R source. When source edits are outside scope, stage a readable exact patch privately and explain how the owner can apply it.

## Add
1. Establish the page's purpose, public content, desired label and navigation position. Inspect existing YAML, page patterns, configuration profiles, consumers and incoming/outgoing links. Reuse authoritative records; do not duplicate facts into page prose.
2. Prefer an existing compatible page pattern. [yaml-records.qmd](../examples/yaml-records.qmd) illustrates a small HTML/R page with a selected field allowlist, empty-record handling and escaped display values. Copy/adapt it to the actual project root; its initial grants mapping is only an example. Set source path, title, visible fields and stable anchors deliberately. Dates/lists/links may need explicit renderers; do not dump arbitrary fields or execute record values as code/raw HTML.
3. Reuse an existing YAML file whenever appropriate. If new fields/files are needed, propose their shape, initial empty [] content, privacy, record validation, relationships and affected CV/page consumers for exact approval. New YAML is not automatically supported by maintenance helpers: extend/test the adapter and validator and explicitly configure any allowlist before promising updates. Do not invent records or publicize private grant amounts or other withheld fields.
4. Show exact new .qmd and _quarto.yml changes together. Add navigation without losing existing items, output paths, resources, theme, site URL or render safeguards. Check actual project.render: a root *.qmd glob already includes a new root page; explicit target lists need the new target. Nested pages require correct execution/data paths and render inclusion. Do not broaden render globs to include instructions, archives or private material.
5. After approved source creation, render in authorized staging or the approved project. Inspect both empty records and representative synthetic records privately; verify escaped characters, missing optional fields and shape errors. Check navigation, anchors, case-sensitive links and assets across affected pages. Rendering is distinct from publication; use existing output/push/Pages permissions and verification. Report unsupported fields/relationships rather than pretending the example is a universal renderer.

## Hide
Clarify whether the user means hide from navigation (still directly accessible), stop publishing the page, or stop maintaining that category. Default to preserving records and source, never deleting YAML or CV entries.

For navigation-only hiding, remove its navigation entry and explain that the page may remain published. For stopping page publication, also exclude its source in project.render (for example, root "*.qmd" plus "!mentoring.qmd"), update/remove inbound links and page listings, and inspect search/sitemap and resource copying. Excluding rendering alone does not remove previously generated/deployed HTML. Preview a clean disposable output; identify exact stale generated artifacts for separately authorized removal in the actual output. Never recursively delete the whole existing output to hide one page. Record/source paths may still be exposed in a public repository; hiding a page is not data confidentiality or removal from Git history.

Confirm that hidden records remain available to other consumers, including the CV and relationship checks. Save selected visibility and any pending source changes in the same private setup note/profile authority; do not invent required config keys. A later show-page request should restore navigation/render targets and verify links without rebuilding records.

## Scope and evidence
This is agent guidance and a reusable example, not an arbitrary page/schema generator. Follow current [Quarto render targets](https://quarto.org/docs/projects/quarto-projects.html#render-targets) and [navigation](https://quarto.org/docs/websites/website-navigation.html) documentation. Test evidence uses a disposable starter: grants added, mentoring excluded, records retained, and empty/synthetic real R/Quarto rendering. No owner-site edit or live deployment is implied.
